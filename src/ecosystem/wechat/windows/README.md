# 本机微信模块

DSH 端代码在 `src/ecosystem/wechat/`，此目录只负责 Windows 微信收发。使用当前的家，不创建第二份 AI、人设或记忆。现有 `/bridge/say` 协议保持原样。

## 当前范围

- 已配置群聊的普通消息只累计账号隔离的群动态元数据（未读数、最后发言人和时间），不因这些消息唤醒模型或注入正文；自己的消息不计未读。计数持久化到原适配器状态库，重启保留，不读未配置群。现有闹钟响起时，在线适配器的新鲜概况会在自定义闹钟措辞之后追加，最多展示 8 个群，未读超过 99 显示 `99+`，不规定是否看群或发言。
- `wechat_history` 成功读取最新页并得到宿主确认后，清零截至该页的未读；翻更早页不会清掉新未读，失败读取也不会清零。概况不包含群消息正文，离线或过期概况不展示；不修改个人 `alarm.md`、`world-prompt.md` 或「我是谁」。
- 接收文字与普通图片私聊、指定家庭群；首启从最新位置监听，不重放旧聊天。原生动图表情仍不接收。
- 收到要交给她的消息后先缓冲（默认 3 秒，`bufferSeconds`）：同一聊天、同一发言人在等待中又发来文字（私聊还包括图片），就重新计时，安静下来后合并为一次模型请求；最长等 30 秒、最多 16 条、合并文字不超过 2000 字，私聊最多两张图片。别人发言、引用、表情包等其他类型让批次立即结束。群聊只有 @ 她的消息会等待，同一人随后的文字合并进来，身份仍是 @ 她的那条。批次开始处理后才收到的消息留在微信数据库中，下一轮按序读取，不中断当前回复。
- 批次成员保留原平台消息 ID，在同一事务中进入待处理与完成状态；缓冲期间不推进游标，处理中断后保留待核对状态，不自动重跑模型。图片单发仅进入会话图片上下文；图片加文字时只把真实文字按原范围归档。图片及附件引用不写入共享记忆块，是否另行留存其中信息由她自己判断。
- 暂不接收视频号分享卡片：卡片会被跳过，不进入宿主会话或共享记忆。视频号卡片解析、视频内容读取，以及朋友圈浏览／发布，均预留为微信模块后续扩展，尚未实现；朋友圈发布需要独立接口，不能复用私聊／群聊发送接口。
- 后台原生发送文字、图片及 GIF 表情，不操作窗口、鼠标、键盘或剪贴板。按 `engine/profiles.json` 中的文件大小与 SHA256 自动选择 Windows x64 微信 4.1.15.13 / 4.1.15.56 / 4.2.0.11 / 4.2.0.12 / 4.2.0.13 的指定构建（4.2 的表情包截取一帧作为图片发送，见下）。未知或匹配不唯一的构建会在加载原生桥前报错。
- 发言人使用真实 wxid，消息保持 `role: user`；昵称只作显示。
- 每个群按平台、登录账号、聊天类型和群 ID 绑定独立会话，列在原房间工作区下，重启继续复用；群名变化不产生新会话。QQ 的相同参数可使用同一映射结构，但本模块仍只提供微信传输。
- 群消息只在微信来源元数据的 `atuserlist` 包含她的真实 wxid 时触发，正文里手打 `@昵称` 不触发。回复携带当前消息之前默认 5 条（控制台可调，1–20）、最多 16KB 的同群上下文，保留各自的发言人 ID；每轮最多读取其中最近两张图片。
- 她发出的文字里写 `@昵称` 只是普通文字，不会真的 @ 到人，被提到的人也不会收到“有人@我”的提醒。原生发送只有文字、图片、表情三种调用，没有 @ 列表；靠操作窗口输入 @ 的做法会抢占焦点，与“不操作窗口、鼠标、键盘”冲突，所以不做。需要点名时让她在文字里写清对方的称呼。
- 支持私聊与群聊中的引用回复（应用消息 49 / 子类型 57）：当前留言与引用的原作者、原消息 ID、类型和内容分别传递。记忆中将留言和明确标为“引用”的文字保留在同一条用户记录里，只引用、不写留言时也保留这次发言，不额外增加一轮。引用图片和表情包只留文字类型与当时的读取状态，附件索引不写入共享记忆；是否另存相册由她自行决定。群聊引用仍沿用真实 @ 触发规则；历史读取使用同一解析。嵌套引用只读取所引用消息的标题，不展开整条引用链。
- 引用图片和表情包时，仅在绑定账号、同一聊天内按原消息服务器 ID 定位，并核对原作者和媒体类型，再复用图片缓存读取或表情包下载校验；缺失、歧义或无法读取时明确标注未读取，保留当前留言。GIF 沿用单帧 PNG 处理，并注明“仅查看首帧”。
- 引用部分的解析或媒体读取错误会在适配器日志与本地 `state.sqlite` 的 `messageFaults` 中记录。完全损坏的应用消息在进入模型前标为 `rejected` 并继续后续消息，不再反复卡在同一条；宿主请求失败、发送结果不明仍保留原有待核对保护，不自动重跑或重发。
- 无需等别人 @，世界会话也可主动调用 `wechat_history` 读取已配置群聊：先用 `wechat_chats` 找到准确 `chatId`，再调用 `wechat_history({ chatId, limit: 10 })`。返回按时间排列的消息、真实发言人、平台消息 ID 和 `nextCursor`；继续看更早记录时把游标原样传回。每页最多 20 条、16KB，使用消息位置游标，翻页期间新消息不会挤乱旧页。图片、视频等媒体先只返回明确的未读取标记，不读取媒体正文；想看某张图片，用该条的 `id` 调用 `wechat_image({ chatId, messageId })`：适配器只在已配置群聊、按本机缓存读取这一张（同一套缓存读取和来源核对），作为下一条消息附给她；图片尚未下载到这台电脑、已不在缓存或 ID 不是图片时明确报错，不推进收消息游标，也不清未读。系统事件不作为群成员发言。读完以返回的同一个 `chatId` 调用 `wechat_send`，再用 `wechat_delivery` 核对结果。读取不自动发言、不改接收游标，也不会把整段群聊写入共享记忆。
- 主动读取复用现有适配器轮询、账号与群白名单、数据库快照和消息身份解析，宿主连接文件协议为 4，并以 `references: true` 声明引用支持。升级时需同时更新插件与 Windows 适配器并重启适配器；新版适配器启动前检查引用能力，旧宿主需先更新，避免只发送留言而静默丢掉引用。旧适配器仍能收发，但无法处理主动读取，读取工具会在 30 秒后明确报超时。关闭微信模块或取消当前回合会结束尚未完成的读取。
- 群图片使用所选账号、群和消息分片的本机缓存，注明原图、缓存版本或缩略图；不操作界面下载。图片尚未缓存或不可解码时，明确标记未读取。图片通过宿主附件服务保存，仅在群会话总日志的上下文事件中保留引用，不进入共享记忆归档。
- 账号和聊天必须显式绑定；进程只根据配置账号的数据库持有情况识别，不选择其他账号。微信退出时暂停收发，原账号重新登录后自动重新绑定进程、重建读取和发送连接，沿用原消息游标，不需要重启 DSH。
- 启动监听、微信重连和手动发送均先执行不发消息的原生 Probe，核对构建指纹、账号和调度器，再处理入站消息或领取发送任务；失败时不调用模型、不推进消息游标、不新建待核对发送记录。监听启动日志及 `Probe` 输出包含实际匹配的版本。`Status` / `Chats` 仍只读，不加载原生桥。
- 自动恢复只处理微信离线；账号或候选进程不唯一、其他运行错误仍明确停止。消息处理过程中中断且结果未确认时，保留待核对状态，不重跑模型、不重发消息，按下文 `Acknowledge` 流程处理。
- 微信请求依次进入原家或对应群会话；她自主调用工具决定是否回复、回复哪个已配置聊天，不广播到桌宠等其他出口。
- `Send` 可向已配置聊天主动发文字。首版需要先停止 `Start` 再单独使用，不支持多进程同时操作微信。
- 世界会话长期提供 `wechat_chats`（分页列目标）、`wechat_history`（主动分页读群消息）、`wechat_image`（按消息 ID 看群里的一张图）、`wechat_send`（指定 chatId 和 1–16 条 messages）和 `wechat_delivery`（按发送 ID 查询结果）。她在桌面聊天、闹钟唤醒或每日回顾时，也能主动查看群聊并联系已配置的私聊和群。主动联系与回复共用同一队列和发送函数，不需要先停监听。`Send` 命令只供停监听后的人工操作。
- 仅调用 `wechat_send` 才安排投递，普通最终文字不自动转发。每批消息按数组顺序发送，可穿插短句、图片和表情；不同批次按入队顺序处理。工具返回 queued 只表示排队，尚未确认发送，不能当作已发出或重复调用。
- 发送正文作为独立的微信出站上下文写入发起会话总日志，按原记忆范围记录真实正文和目标；普通工具参数、回执查询和群图片上下文仍不进入共享记忆。她留在 DSH 的最终文字与微信正文可以不同，归档分别保留。
- 生成时先记为待发送，适配器逐条核对目标聊天中的本人消息、内容及服务器消息编号，再更新同一条记忆的已确认条数。中断则记录已确认部分与结果不明项；这不是对方已读回执。
- 回执先保存在适配器本地，宿主暂时不可用时，重启监听只补报回执，不重发消息。旧版本的待发送记录不会凭空改成已发送。
- 宿主队列保存在世界目录 `wechat-outbox.sqlite`。适配器离线时已排队消息会等待恢复；已领取任务按同一 ID 恢复，适配器已有回执时只补报，不再发送。入站处理结果不明时保留 pending，只暂停这一个聊天的接收（其他聊天照常），日志提示人工核对，独立发送任务仍继续轮询；主动发送的待核对消息 ID 为 `outgoing:<发送 ID>`。结果不明的原发送任务不会重发，其余任务按各自 ID 和回执处理。
- 回执、任务领取、账号状态和群读取结果的单键请求遇到 HTTP 502/503/504 或连接错误时最多尝试 5 次，单次网络超时为 5 秒，间隔 1/2/4/8 秒，每次重读 `wechat.json` 的地址和令牌；响应正文读取中断也按此处理，HTTP 错误保留响应正文（最多 1024 字节）。生成回复的请求仍保留 190 秒网络超时，只发送一次，不能因超时或 503 自动再次调用模型。
- 群会话沿用现有归档范围：`archiveScope: home` 时能读取家的记忆，但群正文不写入共享记忆；群自己的宿主会话日志保留正文，发送状态单独保存，不绕过归档范围。
- `archiveScope: workspace` 会归档家所在工作区的普通会话，包括独立群会话；群图片上下文依旧不进入共享归档。控制台修改范围后重启 DSH 生效，回扫范围内历史并按时间重建近期记忆，保留原始日志和旧归档。

## 账号与风控风险

本模块不是微信官方 API。接收端解密读取所选账号的本地消息数据库；发送端向绑定的微信进程加载 DLL、写入内存并调用内部函数。即使不改微信安装文件、不安装接收 Hook，也不能据此保证账号安全，仍存在账号功能受限或封禁风险。

微信安全中心 [2026 年 1 月 29 日公告（媒体转载）](https://www.thepaper.cn/newsDetail_forward_32493057) 重点治理违规获取聊天记录、联系人数据，以及通过模拟按键、自动化脚本操控微信等行为，同时关注批量操作、营销骚扰及用户投诉。仅用于家庭群、低频聊天，或改用 Computer Use，都不能保证消除接入方式带来的风险。公开资料没有可靠的封号概率或安全发送阈值；进程绑定、版本校验和发送回执用于防止误发、重复发送，不代表通过微信官方授权或风控认证。

## 准备

从旧版升级时，需同时更新并重启 DSH 插件与 Windows 适配器；旧监听器不会消费新的发送队列或识别私聊图片。本版宿主连接文件的 `protocol` 为 `3`；旧宿主不能接收新的私聊图片请求，适配器会明确提示升级，不静默丢掉图片。重启前核对尚未确认的消息，沿用原配置和状态目录，不删除游标或回执。

1. 电脑端手动登录她的独立微信账号。不要把自己的账号填进配置。
2. 运行 `./src/ecosystem/wechat/windows/wechat.ps1 Install`，依赖只安装到 `.host/wechat/.venv`。然后运行 `./src/ecosystem/wechat/windows/wechat.ps1 Build`，需要本机 Visual Studio C++ x64 构建工具。原生桥仅编译到 `.host/wechat/engine`，不改微信安装文件。
3. 在 DSH 的 dsh-world 插件配置开启 `wechat: true`，重载插件/重启宿主并开始世界。模块会写 `<world>/wechat.json`，适配器每次请求都会读取最新地址和令牌。这个文件不得公开。
4. 新建 `.host/wechat/config.json`，按实际登录填写账号、数据库路径和目标聊天；进程自动核对。配置与运行状态不打进发布包。

```json
{
  "account": "wxid_bot_abcd",
  "selfId": "wxid_bot",
  "dbDir": "D:/WechatData/xwechat_files",
  "moduleFile": "C:/Users/you/.dsh/worlds/your-world/wechat.json",
  "pageSize": 50,
  "pollSeconds": 2,
  "mediaRoots": ["C:/Users/you/.dsh/worlds/your-world/room"],
  "chats": [{ "id": "family@chatroom", "name": "家庭群名称", "trigger": "mention" }],
  "people": { "wxid_family_member": "妈妈" }
}
```

`account` 是 `dbDir` 下她的账号目录名，`selfId` 是她的真实微信内部 ID，不是昵称。启动及重连只绑定唯一持有此账号数据库的微信进程，每个连接固定 PID 和启动时间，读取和发送前重复核对。旧配置中的 `processId` 可删除，保留时也不再固定选择旧进程。发送直接使用 `chats[].id`，`name` 仅供显示。表情包不再需要配置目录：她的表情库固定放在 `moduleFile` 同目录的 `stickers/` 下（见下文“表情库”），旧配置里的 `stickerDir` 会被忽略。`mediaRoots` 限制本地媒体发送范围。

统一身份参数如下。微信入站由本机数据库解析；QQ 一列按 [OneBot 11 消息事件](https://github.com/botuniverse/onebot-11/blob/master/event/message.md) 映射，未启用 QQ 传输。

| 内部参数 | 微信来源 | QQ / OneBot 来源 |
| --- | --- | --- |
| `channel` | `wechat` | `qq` |
| `accountId` | 她的 `selfId` | `self_id` 转字符串 |
| `conversationType` | 群为 `group`，私聊为 `private` | `message_type` |
| `conversationId` | 群的 `...@chatroom` 或私聊 wxid | 群用 `group_id`，私聊用 `user_id`，均转字符串 |
| `conversationName` | 配置的聊天显示名 | 群显示名（由适配器取得） |
| `speakerId` | `wechat:` + 本行分片解析出的 `sender_username` | `qq:` + `user_id` |
| `speakerName` | 显式 `people` 名称或联系人备注/昵称 | 群名片 `sender.card` 或昵称 |
| `platformMessageId` | 本行消息分片名 + `local_id`；与账号、会话一起定位 | `message_id` 转字符串 |
| `mentionIds` | 当前触发消息真实 `atuserlist`，每项加 `wechat:` 前缀 | `at` 消息段中的账号，加 `qq:` 前缀 |

平台账号 ID 不按同名自动合并。微信的分片内数字 `sender_id` 不能直接当人 ID。QQ 的 @ 使用 [消息段的 `at.data.qq`](https://github.com/botuniverse/onebot-11/blob/master/message/segment.md#某人)，同样不通过昵称判断。

`wechat_send` 的 `messages` 每项为 `{ "type": "text", "text": "一句话" }`、`{ "type": "image", "path": "绝对路径" }` 或 `{ "type": "sticker", "stickerId": "st_..." }`；表情也接受允许目录下的 `path`。图片会快照成 PNG，表情转成 GIF 并保留动画；每条文字最多 4094 UTF-8 字节，GIF 最大 1MB、1024 像素边长，过大时明确报错。

```powershell
./src/ecosystem/wechat/windows/wechat.ps1 Status
./src/ecosystem/wechat/windows/wechat.ps1 Probe # 原生账号/调度器校验，不发消息
./src/ecosystem/wechat/windows/wechat.ps1 Chats -Limit 20 -Offset 0
./src/ecosystem/wechat/windows/wechat.ps1 Start -AllowSend
# Ctrl+C 停止监听；然后才能单独主动发送。
./src/ecosystem/wechat/windows/wechat.ps1 Send -Chat 'family@chatroom' -Text '一条明确要发送的话' -AllowSend
# 隐藏后台窗口运行；停止时核对尚未完成的消息。
./src/ecosystem/wechat/windows/wechat.ps1 Start -AllowSend -Background
./src/ecosystem/wechat/windows/wechat.ps1 Stop
```

**让插件管理适配器（可选）**：在 dsh-world 配置里与 `wechat: true` 并列写入

```yaml
wechatAdapter:
  python: C:/path/to/.host/wechat/.venv/Scripts/python.exe
  config: C:/path/to/.host/wechat/config.json
```

两项都填才生效。微信模块启动时插件用等同于 `Start -AllowSend` 的参数拉起适配器，微信模块停止（控制台停止、重启 DSH、退出）时结束整个进程树，适配器意外退出则按 1 秒起翻倍、最长 30 秒的间隔自动重启；日志写在 `<world>/wechat-adapter.log`（超过 1MB 时清空）。**写下这两项即视为长期允许适配器发送消息**，默认关闭。启用前先用 `wechat.ps1 Stop` 停掉手动启动的实例，否则两个实例会争用单实例锁。入站 pending 只暂停它所在聊天的接收并在日志提示，其他聊天和独立发送队列继续运行；若适配器以需要人工核对的退出码 2 退出，插件不会重复拉起。核对后先停适配器，使用 `acknowledge` 处理，再从控制台重启。启动时若 Python、配置或脚本暂时缺失，插件会按同样的间隔重试，文件回来后自动启动。微信自身重启不需要插件处理：适配器会等待同一账号重新登录并沿用游标，控制台「微信」卡片会显示“微信离线，等待重新登录”。

`Start -AllowSend` 会把所选聊天的新文字交给家的 Agent，并实际发送回复。家仍有原来的工具权限，第一版不会把群成员自动变成独立权限主体；接入群聊前应决定允许哪些人向家下指令。

若提示待核对消息，先到家和对应微信聊天检查是否已处理、已发送。确认不需要自动再处理这一条后：

```powershell
./src/ecosystem/wechat/windows/wechat.ps1 Acknowledge -Chat 'family@chatroom' -MessageId 'message/message_0.db:123'
```

这会标记该条已核对并继续，不重发。其他消息记录保留。`Acknowledge` 不需要 `-AllowSend`，也不连接原生发送引擎；`-Chat` 和 `-MessageId` 必须与待核对记录一致。自行生成过回复不能证明微信已送达，不会据此自动清除 pending。

升级前保留配置文件所在目录下的账号子目录（含 `state.sqlite`）、`engine` 和 Python 环境。不要依赖包管理器保留 `node_modules/dsh-world/.host/wechat`；安装在包目录中的运行数据应先完整备份或移到包目录外，并同步调整 `wechatAdapter.python`、`wechatAdapter.config` 及手动命令的 `-ConfigFile`。仅在包内修改 `adapter.py` 的热补丁会被升级覆盖。

## 表情库

她自己的表情库在 `moduleFile` 同目录的 `stickers/` 里：`index.json` 加 `files/` 里的图片，每张只有名称和 1–8 个标签（标签就是摘要），没有表情包分组。最多 500 张，单张 10MB 以内，按图片内容去重，只收 GIF、PNG、WebP、JPEG。

- `sticker_search`：按关键词查名称和标签，返回最多 8 张（最多 20）的 `id｜名称｜标签`，不带关键词看最近收的。不会一次倾倒整个库，也不会把图片发给模型。
- `sticker_save`：把聊天里别人发来的表情包收进库。适配器按消息 ID 在已配置的私聊或群聊里取出原始表情（腾讯 CDN，md5 与消息一致才接受，保留动图），暂存在 `stickers/incoming/`，宿主核对后收下并删掉暂存。群里的表情在 `wechat_history` 中显示为“表情包，未读取”，用那条的 `id`。
- `sticker_edit`、`sticker_remove`：改名称标签、删除。
- 发送仍是 `wechat_send` 的 `{ "type": "sticker", "stickerId": "st_…" }`；表情不在库里时排队就会被拒绝，不会等到发送时才失败。发送结果只返回文字，不把图片回传给模型。

从旧的 DeepSeek-meme 插件迁移（只需一次，旧目录只读不改，重复运行不会重复导入；编号、名称和标签保留，分组和长段含义不导入）：

```powershell
node <dsh-world 包目录>scriptsimport-stickers.mjs C:Usersyou.dshmemes C:Usersyou.dshworldsyour-world
```

导入后可以在 DSH 的 profile 里去掉 `dsh-deepseek-meme`。QQ 仍用它自己的收藏表情，与这里无关。

## 验证边界

单元测试不连接微信。读取仍使用所选账号的本地数据库；发送桥加载到已绑定的微信进程，在微信自己的任务线程提交操作，不使用界面发送。停止适配器会取消尚未提交的原生任务；已交给微信的异步发送不能撤销，结果不确定时仍需人工核对。桥在微信退出时释放，未安装接收 Hook。

这不是微信官方 API。版本变更需重新校准，锁屏和群聊等实际条件必须分别验证。`engine/` 基于第三方原生 ABI 研究定制，保留独立的非商业许可与来源说明；该目录不适用仓库根目录的 MIT 许可。

4.1.15.56 的指纹与 19 个原生地址映射来自 [helper 的版本表](https://github.com/Prometheus-first/helper/blob/main/native/core_version.h)。两版沿用相同请求 ABI、账号核对和消息对象字段布局；版本表选择、地址编码及未知构建拒绝由离线测试覆盖。上游已实测新版文字收发及桥接加载卸载，媒体未逐项重做真实网络操作，详见其 [验证范围](https://github.com/Prometheus-first/helper/blob/main/native/README.md)；本项目实测范围见下方日期记录。本次仅更新 Python 和版本表，无须重新编译未改动的 C++ 桥；新增构建或结构发生变化时仍需校准并实测。
