# 她自己的浏览器与她学会的操作

DSH 端代码在 `src/ecosystem/computer/`。插件只提供一个她自己的浏览器和一组通用的页面原语；不含任何平台（B 站等）的代码。某个网站怎么用，由她自己用原语摸索，走顺了就按分类存进她的操作目录，以后直接回放；网站改版把操作弄坏了，由她自己重新走通再存。使用当前的家，不创建第二份 AI、人设或记忆。

## 开启

- 在世界控制台「接入」里打开「她的浏览器」，默认关，不用改配置。（0.8.0 要在配置里写 `computer: true`；0.8.1 起不需要了，写着的也不碍事。从 0.8.0 升上来时，控制台开着、但配置里那一行已经删掉或写成 `false` 的，升级后是关的。）要用 Windows 上装的 Edge 或 Chrome，找不到时这一行写着用不了。
- 控制台概览的「接入」卡片里出现开关「她的浏览器」，默认关；卡片下有 Edge 状态（找不到 Edge / 未打开 / 运行中）、她按分类学会的操作、每类有没有她写的说明、各自最近一次结果，以及「打开她的浏览器」按钮。
- 第一次用时她的浏览器窗口出现在桌面上。要登录某个网站，请在那个窗口里自己扫码或输入，登录态留在 `<world>/browser/`。

## 浏览器

- 用系统自带的 Microsoft Edge（也会找 Chrome），以 `<world>/browser/` 为独立配置目录，开可见窗口，通过 DevTools 协议（CDP）控制。不是你日常用的那份 Edge，也看不到你的书签和登录。启动时关掉扩展和同步（`--disable-extensions`、`--disable-sync`）：Edge 可能用 Windows 账号自动登录新配置，把你的扩展和书签、自动填充同步进来，扩展还会在每次启动时弹出欢迎窗口、往她读的网页里插东西。已经同步进来的数据不会自动清除，要清就在她的浏览器里打开 `edge://settings/profiles` 退出账号并清除这台设备上的数据。
- 所有操作都是浏览器内部派发的输入事件，**不使用你的鼠标和键盘**，窗口被别的东西挡住也照常工作。
- 编号在同一个标签页里不重复；页面里元素没了，旧编号会报错让她重读，不会点到别的元素上。点击时目标被别的元素盖住会拒绝。输入会替换输入框里原有的内容。
- 世界停止或关闭模块时，插件断开连接并清空等待中的操作，不关 Edge 进程（关掉会丢她开着的页面），由你自己关。Edge 被关掉后，下次她用时重新打开。

## 她用电脑

除了她自己的浏览器，她也能用你的电脑：调出桌面上的程序、看、点、输入。

- **开启**：控制台「接入」里的「她用电脑」，默认关，要先打开「她的浏览器」，不用改配置（0.8.0 要写的 `computer: true`、`desktop: true` 已经不需要）。只支持 Windows，别的系统上这一行写着用不了。
- **不装任何东西**：底下是插件自带的一个 PowerShell 脚本 `desktop/win32.ps1`，用 Windows 自己的接口：`PrintWindow` 截窗口、`PostMessage` 投鼠标和键盘消息、`ShowWindow` 还原窗口、UI Automation 点托盘图标、开始菜单（`Get-StartApps`）启动程序。没有 npm 依赖，也没有原生库。
- **在后台操作**：点击、输入、按键都直接投给那个窗口，**不移动你的鼠标指针、不抢焦点**，你在用电脑时她也能用；被别的窗口挡住也照样截得到、点得到。Ctrl、Shift、Alt 组合键要让程序读到修饰键，会短暂共用那个程序的键盘状态，随即还原。
- **调出程序**：`open` 先找开着的窗口：标题就是这个名字或以它开头，程序文件名是它，标题以「- 这个名字」结尾（「下载 - 文件资源管理器」）；都对不上时查开始菜单里叫这个名字的程序，再按它的程序文件或商店应用 ID 找它开着的窗口，所以窗口标题是英文的记事本（「Untitled - Notepad」）说「记事本」也找得到，不会再开一个。最小化的原地还原、不激活。没有窗口就去托盘找它的图标（先看任务栏上的，再看「显示隐藏的图标」里的）点一下，这是程序自己把窗口调出来；从外面强行显示它藏起来的窗口不行，那样的窗口不刷新也不接收输入（她用 PowerShell 试过）。托盘里也没有才从开始菜单启动。点托盘或启动之后，程序会把自己拉到前台，所以随即把焦点还给你原来的窗口。程序已经在跑却既没有窗口也没有托盘图标时不再启动：微信 4.x 再启动一次会多开一个，这一步用系统的 `tasklist` 查进程。
- **窗口不见了**：每次截图、放大之前都先确认窗口还在、没有最小化，不在就告诉她重新 `open`。微信主界面按 Esc 会收进托盘。
- **收回**：关掉「她用电脑」开关。正在执行和排队的动作立刻失败，脚本进程结束。不需要等她这一回合结束。
- **怎么看**：只给截图，像人一样看图操作。截图是窗口的客户区，按真实像素截（脚本是每显示器 DPI 感知的，缩放屏上坐标也对），长边缩到约 1280 像素；她按图上的像素点，插件换算回窗口。每次操作完都会再给一张新截图，让她自己确认做对了没有；点击之后的截图上用红圈标出实际点到的位置（她在微信发表框上两次点在「发表」按钮上沿外面一点，自己看不出偏在哪）：投递的消息程序收没收、有没有反应，Windows 不会告诉发送方。不做 OCR：她自己能看图。
- **出错隔离**：脚本在单独的子进程里。退出或一次调用 30 秒没回应都会登记故障，下一次用时重新启动；连续两次一启动就死（比如 PowerShell 编译不了它带的 C#），就停在故障里，不反复拉起，直到开关关了再开。
- **记录**：控制台「她的浏览器」卡片下显示脚本在不在跑、她最近 5 个动作（动作、程序、成没成），不记她输入的文字。截图只经过临时文件，读完就删。

`desktop` 一个工具，`action` 取一种：

| action | 作用 |
| --- | --- |
| `open` | `app` 写程序名（窗口标题、程序文件名或开始菜单里的名字，比如「微信」）：开着的用它的窗口，托盘里的从托盘点开，没开的启动；不写 `app` 就列出开着的窗口 |
| `shot` | 再截一张当前窗口 |
| `click` | `x`、`y`（截图上的像素）；`double` 为真双击，`right` 为真右键；`hold` 是按住的秒数（长按，最多 10 秒，可和 `right` 一起用） |
| `drag` | 从 `x`、`y` 按住拖到 `x2`、`y2` 再松开，中间分 20 步移过去；`hold` 是先按住几秒再开始拖（要长按才能拖起来的东西），`right` 用右键。后台模式下按住和拖动期间，那个窗口读到的鼠标键（`GetKeyState`，WinForms 就这样读）也是按下的；直接读真实鼠标键盘的程序（很多游戏）仍然看不到，按住或拖动之后截图一点没变时会告诉她，请伙伴切到前台模式 |
| `type` | `text`；先给 `x`、`y` 就先点那里；`submit` 为真时再按回车 |
| `press` | `key`：回车、Tab、Esc、空格、退格、Delete、Home/End、翻页、方向键、F1–F12、单个字母或数字，可加 `ctrl+`、`shift+`、`alt+`；`hold` 是按住的秒数（最多 10 秒，比如游戏里按住 w 走路） |
| `scroll` | `direction` 为 up/down/left/right，滚三格；可加 `x`、`y`，默认窗口中间 |
| `zoom` | 截图上 `x`、`y` 到 `x2`、`y2` 的一块，按窗口原分辨率截下再放大（最多 4 倍） |

程序的对话框和面板（微信的「朋友圈」发表框、「选择文件」）是主窗口之外单独的窗口，截图里没有它们；每次截图后都会告诉她这个程序还开着哪些别的窗口，`open` 写窗口标题就切过去。

桌面上走通的步骤也能存进操作目录：后台模式走通的写 `"where": "desktop"`，前台模式走通的写 `"where": "screen"`。步骤取 `open`（程序名或窗口标题）、`click {x,y,double?,right?,hold?}`、`drag {x,y,x2,y2,right?,hold?}`、`type {text,x?,y?}`、`press`（可加 `hold`）、`scroll {direction,x?,y?}`、`wait {seconds}`；向外发出的步骤照样标 `outward`。`x`、`y` 是截图上的像素：`desktop` 是那个窗口的截图（窗口挪了位置不影响，大小变了按比例跟着变），`screen` 是整个屏幕的截图（回放前先截一张，按这块屏幕的大小换算）。每种只在它自己的模式下回放：`screen` 的操作在后台模式下跑会被拒绝，并告诉她要请伙伴切到前台。回放时步与步之间不停，而手动做时她每一步之间都隔着几秒，点完才弹出来的窗口（「选择文件」、发表框）她从没意识到要等。所以：操作时，截图后告诉她这个程序的窗口出现了或关掉了哪些、在上一次输入之后多少秒内；保存时，紧跟在输入后面、中间没有 `wait` 的 `open`（切到窗口）和一个 `outward` 都没标的操作会被指出来（只提醒，照样保存）；回放在这样的 `open` 上停下时，也会说可能是窗口还没出来。`procedure_run` 不调模型逐步回放，跑完（或在哪一步停下）把最后一张截图给她，由她看做成了没有。不能用 `onAlarm`、`summary`、`messages`：桌面上读不出文字，也不该在闹钟前没人看着时动伙伴的电脑。

### 两种模式：后台和前台

「她用电脑」打开就是**后台模式**：她看某一个窗口的截图，输入直接投给那个窗口，不动你的鼠标、不抢焦点，你用着电脑她也能用。它够不着以管理员权限运行的程序（很多游戏和它们的启动器）：截图和点击都会被 Windows 挡掉。遇到这种窗口她会直接被告知「后台模式截不到、也点不了它，请伙伴切到前台模式」，不会换别的办法硬做。

控制台「接入」里的「她用电脑」是一个三选一：关闭 / 后台 / 前台。**前台模式**：

- 切到前台时弹出一次 Windows 的管理员权限确认（「她用电脑」原来关着的，会先打开它再切）。确认后插件起一个以管理员权限运行的助手，这一次一直有效，之后每一步都不用再确认。拒绝或 2 分钟内没确认，开关就不打开，控制台上说明原因。
- 它不记在 `world.json` 里：换回后台、关掉「她用电脑」、或者 DSH 退出重启，管理员助手就结束，下次要用得重新确认。
- 开着的时候她的 `desktop` 工具换成前台版：看整个屏幕（多块屏幕拼在一起），用真的鼠标和键盘按截图上的位置操作，游戏和管理员程序都能用。你的鼠标会跟着动，最前面的窗口会变，所以这是你把电脑交给她的时候用的。
- 管理员助手只做截图、鼠标、键盘和画提示这几件事；列窗口、从开始菜单启动程序仍由普通权限的助手做，她打开的程序不会以管理员身份运行。它和 DSH 之间走一条只有这次知道名字的管道，先对一次性的口令，别的程序连不上。
- 提示是整个屏幕一圈蓝色柔光加顶上的胶囊；它们不会出现在她的截图里。叫停的方式和后台一样。
- 前台模式下走通的步骤存成 `"where": "screen"` 的操作，以后在前台模式下用 `procedure_run` 回放（游戏里的每日任务这类重复的事，跑一次只算一步）。
- 游戏的用户协议通常禁止自动化操作，长时间让她代打有封号的风险，由你自己决定。

### 她操作时你看得到，也随时能叫停

她用 `desktop` 动手时（看截图、点、输入、录制都算；回看录好的不算），屏幕顶部正中浮出一个深色胶囊：蓝点缓慢呼吸，写着「<她的名字>正在操作」，旁边是「连按两下 Esc 停下」和一个「停下」按钮；她操作的那个窗口四周有一圈蓝色的柔光边。后台模式下最后一次动作约 5 秒后两者消失；前台模式下她每一步要想一会儿，所以停约 30 秒才消失，边框是贴着整个屏幕边缘的一圈。长录制期间一直在。前台模式里游戏自己也常是「总在最前」的窗口，她每点一下游戏就会盖过来，所以胶囊和边框会一直被放回最前面；游戏若是「独占全屏」，任何窗口都盖不上去，要在游戏设置里改成「无边框窗口」或「窗口」才看得到。胶囊上的字全由程序决定，不显示她填的程序名；操作的是哪个窗口看边框就知道。它们不抢焦点，也不出现在她的窗口列表里；边框不挡鼠标。

叫停：半秒内连按两下 Esc，或点胶囊上的「停下」。单按一下 Esc 照常给你自己的程序。按下后：

- 她正在做的那一步作废，她收到「伙伴按了停下……别重试，先问问伙伴」；正在录的立刻停在那里，之后不再给那个窗口发任何按键（包括自动暂停）。
- 按下时她没有正在做的那一步（比如胶囊还没消失，或者她在长录制期间去做别的了），会另外送一句话进她的家告诉她。
- 在你下一次跟她说话之前，她所有动电脑的操作都会被拒绝；回看已经录好的还可以。你开口（DSH 里、桥、微信或 QQ 进家里的话都算）就放开。

胶囊画不出来时她照常操作，问题记在控制台的健康状态里。

### 看会动的东西（视频）

她一次只能看静止的图，所以"看视频"是先录、再看录下来的：

- **录**：`desktop record`，先让视频播起来，再录当前窗口。`seconds` 是录多久（最多 600 秒），`every` 是每几秒截一帧（默认 1 秒，最多 600 帧）。120 秒以内会等到录完，直接给全片的拼图；更长的马上返回，她可以去做别的，录完再看。一次录的是她定的那一段，不是视频本身的长度：录完会提醒她，视频还没放完可以再录一次接着看，再录会换掉上一段；不想再看了就停下，不用看完。
- **停**：`desktop stop` 把正在录的长录制中途停下，已经录到的照样能看。
- **录完自动暂停**：录制结束（或被 `stop`）时如果画面还在动，程序替她按一下空格，绝大多数播放器是暂停；随后再看两眼确认停没停住，并如实告诉她。下一次录同一个窗口时先按一下空格接着放。她自己动过那个窗口（点击、按键、输入、滚动）之后就不再自动接着放。画面本来就不动时不按，免得把暂停的视频按成播放。这是一次碰运气的按键：播放器没有焦点时空格可能滚动页面。不想要就带 `pause: false`。
- **粗看**：`desktop review` 不带参数，从整段录制里均匀取 12 帧拼成一张图，每格左上角标着第几秒。一张图的花费看完全片。
- **细看**：带 `from`、`to`（秒）看其中一段，同样最多 12 帧；带 `at`（秒）看那一帧的原图。看的是录下来的帧，不用重放。

录制就是按固定间隔对那个窗口截图，用的是和 `shot` 同一种后台截图：窗口被盖住也能录，不抢焦点；窗口最小化或收进托盘就录不了，会停下并告诉她。帧存在系统临时目录里，下一次录制开始、或者关掉「她用电脑」时删掉。

做不到的：没有声音；动作和节奏这类靠连续画面才看得出的东西会丢；有版权保护的视频和少数直接用显卡出画面的播放器截出来是黑的或不动的。几乎每一帧都和上一帧一样时她会被告知"画面没在动"；这是把每帧缩成 16×16 的灰度图来比的，暂停画面上转动的加载圈不算在动。

## 信箱

没有通道的地方，她怎么知道有人找她：程序替她看任务栏，有程序在叫时汇总成一句话送进家里。看不看、回不回由她定，程序不替她打开任何东西。跟着「她用电脑」的开关走：后台、前台都开着，关掉就停（只支持 Windows），没有单独的开关；不理会哪些程序在控制台「接入」里改。

- **看什么**。任务栏上所有程序的两种动静：按钮在闪（程序要你注意它），和系统通知（带一小段原话，最多 60 字）。不按平台写任何东西；程序名取它自己的说明（比如「Microsoft Edge」），不读窗口标题，标题里可能有消息内容。通知的程序名取 Windows 显示的名字，没有就从应用 ID 里取（`…\powershell.exe` → `powershell`），一个没登记的 ID 发的通知 Windows 不给来源，写成「没署名的程序」，每一行都有名字。
- **不看什么**。DSH 自己（`DeepSeek Harness`，通知 ID `electron.app.DeepSeek Harness`）永远不算：那是她的家，它弹的通知里是她自己的话，告诉她就成了一条新消息，她回完又是一条，自己跟自己没完没了地说下去（#61）。走自己通道的程序也不算：微信模块开着时的微信、QQ 模块开着时的 QQ，免得同一条消息到她那里两次。
- **默认不理会 Windows 自己的程序**（#61）：控制台窗口（`conhost`、`OpenConsole`）、远程桌面（`msrdc`、`mstsc`）、资源管理器（`explorer`），以及 Windows 自己的通知（`Windows.SystemToast`、`Microsoft.Windows`）。它们不会是有人在叫她：DSH 启动时，控制台窗口和远程桌面（WSLg 跑在它上面）重画窗口的样子和按钮在闪一样，她以前每次都要花一轮去找一个任务栏上并没有的按钮。按程序的 exe 名和通知 ID 写，换了显示语言也认得。
- **名单在控制台里改**。「接入 › 她用电脑」下面一行：删掉默认里的、加上自己的（写她听到的名字，或程序的 exe 名，不分大小写；写 `Microsoft.Windows` 也算上 `Microsoft.Windows.` 开头的），「最近报过」列着这次启动以来告诉过她的程序，点一下就不再报；「恢复默认」回到上面那份。改了下一次看任务栏就照新的来，不用重启。存在 `world.json` 的 `inboxIgnore`，和默认一样时不写。
- **任务栏之外的不管**。网页、朋友圈这类任务栏上没有动静的地方，程序不去看；每句话末尾提醒她这些要自己去看，看过的地方和怎么看记进自己的笔记，一点一点教她。
- **什么时候告诉她**。动静往往一阵一阵来：最后一个动静之后 10 秒内没有新的，就把这一阵合成一句话送过去，每个程序一行。她正在一轮里时不打断，等她闲下来再送。
- **不落盘**。启动时已经在通知列表里的算旧的；关着的那段时间里来的不会补报。
- **看不到就是故障**。读不到通知（没有权限）、听不到任务栏、助手起不来，都会出现在控制台的健康状态里。
- 每 2 秒问一次，用的是和「她用电脑」同一个脚本、另一个子进程，她操作得慢的时候信箱不跟着等。

## 工具

只挂在家会话里，工作间和别的会话看不到。

| 工具 | 作用 |
| --- | --- |
| `page_open` | 在她的浏览器当前标签页打开地址，返回页面内容（同 `page_read`） |
| `page_read` | 读页面：每个可操作元素一行 `[编号] 角色 名称`，之后附可见文字；`page` 翻页，`ref` 只看某元素里面 |
| `page_click` | 点编号对应的元素；`hold` 是按住的秒数（长按，最多 10 秒），和 `desktop` 的 `hold` 同一个上限、同一种说法。存成操作时 `click` 步骤也能写 `"hold": 2` |
| `page_type` | 在编号对应的输入框里整段输入（中文也行）；`submit` 为真时再按回车 |
| `page_press` | 按一个键 |
| `page_scroll` | 向上或向下滚一屏左右，可指定元素 |
| `page_wait` | 等某段文字出现（最多 60 秒），或检查某个编号还在不在 |
| `page_shot` | 截当前页面一张图附在下一条消息里；只在读文字看不明白时用 |
| `page_eval` | 在当前页面里执行一段 JS，返回 JSON；十秒超时，结果截到 2000 字；只在她的浏览器页面里执行 |
| `computer_use` | 用电脑之前说这次要用的程序或网站（`target` 只写对象，比如「微信」「B站」），返回这一类里她写的说明、操作名和文件所在的文件夹；不说就只列出有哪些分类 |
| `procedure_run` | 跑一个学会的操作：`path` 写 `分类/操作`，`args` 是它声明的参数；不调模型，逐步回放 |
| `procedure_save` | 把走通的步骤存成一个操作，放进它的分类；不带 `json` 调用时返回完整的格式说明（格式很长，只在要写时才给她，不随每一步发送） |
| `procedure_note` | 写某一类的说明（对应哪个程序或网站、网址和别称、要注意什么），整份替换，最多 1000 字 |
| `desktop` | 她用你的电脑（只在「她用电脑」开着时有），见上一节 |

返回都很短：页面读取按页截断，脚本结果截断，截图不会自动附带。

## 操作目录

她学会的东西不再一个操作注册一个工具，工具列表固定是上面这 13 个，不随她学新东西而变（保存操作也不会让宿主的提示词缓存失效）。用法是先 `computer_use` 说要用什么，看到相关的操作再 `procedure_run`；没有合适的就用 `page_*` 自己做，走通了 `procedure_save` 存进来，再用 `procedure_note` 写这一类的说明。

`computer_use` 只认对象，做模糊匹配，和记忆检索一样不建索引、不做向量：她说的词只和分类名、她写的说明比，逐词比，大小写不论。一个词包含另一个就算对上（「B站私信」对上「B站」，「打开微信」对上「微信」）；不包含时，相邻两字有六成以上相同也算（「bilbili」对上「bilibili」）；只是零散地有几个字相同不算，免得说明里的「消息框」把「发送消息」带出来。操作名和描述不参与：同叫「发送消息」，B 站的和微信的是两回事，一起召回只会分散注意力。所以 `computer_use` 写「微信」能找到微信那一类，写「发送消息」什么也找不到。一次只返回一类：她写的说明（截到 500 字）、一行操作名（按文件时间从新到旧，最近保存或手改过的在前）、文件所在的文件夹。操作都是简短的一件事，名字就说清了做什么，所以不附描述、不分页；要看某个操作的参数和步骤，她自己读那个 `<名字>.json`。好几类对得一样好时，只列出这几类的名字，让她说具体是哪一类；一个都对不上时，照实说没有，列出已有的分类，并提醒她：要是其中一类，就在它的说明里补上这个叫法。

## 操作文件

`<world>/procedures/<分类>/<名字>.json`，每类她自己写的说明是 `<分类>/目录.md`。`procedure_save` 的说明里写明了这个目录，她可以用文件工具直接读和改，改了下次查目录、跑操作时就生效。保存时插件先校验，不合格不落盘并说明哪里不对（文件里写了不认识的键也会被拒绝，免得一个拼写错误悄悄变成"任意链接"）；同名覆盖前，旧版本存成 `<名字>.v<n>.json`，说明的旧版本存成 `目录.v<n>.md`。格式不合格的文件、文件名和 `name` 对不上的、`category` 和所在文件夹对不上的，都跳过并登记故障，不影响其他操作。

顶层字段：

| 字段 | 说明 |
| --- | --- |
| `name` | 操作名，也是文件名：文字（中文也行）、数字、下划线、连字符，1 到 40 个字，不能是「目录」 |
| `category` | 分类，也是文件夹名，规则同 `name`；不写时保存进「未分类」，手放的文件取所在文件夹 |
| `description` | 她自己写的说明 |
| `params` | `{ 名字: { type: string｜number｜boolean, required?, description? } }` |
| `steps` | 1 到 40 步，每步只有一个动作 |
| `onAlarm` | 为真时每次闹钟前自动跑一次；不能有必填参数，也不能有向外发出的步骤 |
| `summary` | 闹钟前那一行的模板，可用 `{{count}}` 和脚本 `as` 存下的值 |
| `messages` | 把 `extract` 的行写进归档，见下文 |

步骤（文字里的 `{{参数}}` 会代入）：

| 动作 | 写法 |
| --- | --- |
| `open` | 地址 |
| `click` | 锚点 |
| `type` | `{ into: 锚点, text }` |
| `press` | 键名（与 `page_press` 相同） |
| `wait` | `{ text｜anchor｜url, seconds? }`，最多 60 秒 |
| `check` | `{ text｜anchor｜url }`，最多等 3 秒，还不满足就停 |
| `extract` | `{ list: 锚点, fields: { 名: 锚点, 可加 attr }, limit? }`，`limit` 默认 8、最多 20，字段最多 12 个；字段只写 `attr` 时读列表项自己的属性 |
| `script` | JS，可 `return`；`as` 把结果存成值 |

`extract` 和带 `as` 的 `script` 可加 `allowEmpty: true`，表示这一步本来就可能是空的（比如没有未读），见下文。

`click`、`type`、`press`、`script` 可加 `outward: true`，表示这一步会向外发出东西。锚点是 `{ role?, name?, text?, css?, nth? }`，`role`、`name` 取 `page_read` 里看到的，至少给一个；`nth` 从 0 数。操作里不存坐标，也不存快照编号。

```json
{
  "name": "看未读",
  "category": "bilibili",
  "description": "看 B 站消息页的未读",
  "onAlarm": true,
  "summary": "私信 {{count}} 条",
  "steps": [
    { "open": "https://message.bilibili.com/" },
    { "wait": { "text": "我的消息" } },
    { "extract": { "list": { "role": "listitem" }, "fields": { "who": { "role": "link" }, "text": { "role": "paragraph" } }, "limit": 8 }, "allowEmpty": true }
  ]
}
```

回放遇到找不到的锚点或不满足的 `check` 就停，返回第几步、期望什么、当前页面的简短快照。带 `outward` 的步骤失败一律报"未完成"，不自动重试。

**空的也算没跑通。**`extract` 一条都没有、某个字段每一条都是空的、带 `as` 的 `script` 结果为空（`null`、空字符串、空列表或全空的对象），都按失败报出第几步，不再返回"完成。"或空结果。网站改版后选择器找不到东西，最常见的样子就是"什么都没有"，不报错的话她会以为"没有新私信"。本来就可能为空的那一步标 `allowEmpty: true`。

**新版不行就退回旧版。**最新版没跑通、而且还没有任何向外的动作时，按从新到旧再试最近 2 个旧版本（`<名字>.v<n>.json`，和较新版本完全相同的、已经不合格式的、参数对不上这次调用的跳过）。网站灰度或 A/B 测试时新旧页面会同时存在，为新页面修的版本到旧页面上可能跑不通。旧版本跑通了就用它的结果，后面附一句"最新版第几步没跑通，这次退回第几版"，控制台里也记着；闹钟前那一行后面注"用的第几版"。全都不行时，报最新版的失败。

这两条的依据是模拟站点上的对比实验：空结果算失败后，不报错的失败从 105 次回放降到 0；退回旧版后，修复把旧页面修坏的从 9 次降到 0，学会、改版、修复全程走通的操作从 9/25 升到 16/25。

## 闹钟前回放

闹钟响起前，插件在一个单独的标签页里依次跑所有 `onAlarm` 的操作（整体约 60 秒，单个约 20 秒），跑完关掉这个标签页，不打扰她正在用的页面。每个操作留一行（以 `分类/操作` 开头），接在闹钟文字（和微信群动态）后面，成功或失败都照实写：

```
bilibili/看未读：私信 2（阿明）
bilibili/看未读 没跑通（第 3 步找不到「回复我的」）
```

失败或超时不会拖住闹钟：闹钟不带这一行照样送出，同时登记一条故障。闹钟前的回放不在任何会话里，**不写归档**。

## 归档

操作可以用 `messages` 声明：`extract` 出来的哪些行是消息、各字段对应归档的哪一项。字段是 `channel`、`conversationType`（`private` 或 `group`）、`accountId`、`conversationId`、`messageId`、`speakerId`、`content` 必填，`speakerName`、`conversationName`、`occurredAt`、`outgoing` 可选；除 `channel` 和 `conversationType` 写死外，其余是 `{{字段}}` 模板，`outgoing` 算出 `true` 表示是她自己说的。

- 只有她自己在家会话里用 `procedure_run` 跑操作时读到的才进归档（`archive.sqlite`，`memory_find` 能找到）；按平台消息 ID 去重，再读一遍不会重复。
- 只在归档范围内写入；会话不在范围里时，结果注明"没有记"。
- 身份字段缺失或不合格的行跳过，结果里写"跳过 n 条"。
- 写归档失败不会让她的操作失败：读到的结果照给，后面补一句没记进去的原因。

## 文件位置

| 位置 | 是什么 |
| --- | --- |
| `<world>/browser/` | 她的浏览器配置，**含各网站的登录态**，不要外传、不要放进云盘或仓库 |
| `<world>/procedures/` | 她的操作 `<分类>/<名字>.json`、旧版本 `<名字>.v<n>.json`（每个名字只留最近 2 个，保存时删掉更早的；说明 `目录.v<n>.md` 同样）、她写的说明 `<分类>/目录.md`；这些是她的原件，插件只在她保存时写 |

备份世界目录时这两个都会带上，注意第一个的内容。

## 对三批人

1. **没用过插件的新用户**：默认关闭，什么都不变。打开后目录是空的，`computer_use` 照实说"还没有学会的操作"，从零开始由她摸索；归档里没有平台记录，直到她的操作第一次读到消息。
2. **已经用过插件的老用户**：不加表，不改任何已有文件。新增目录 `<world>/browser/` 和 `<world>/procedures/`。模板、她自己的 `alarm.md`、日记、自述不动；闹钟前的那一行接在模板渲染之后。操作文件和说明是她的原件，插件只在她保存时写，并保留旧版本。
   - 在这个功能的开发版里存过工具的：`procedures/` 下平铺的 `<名字>.json` 原地读成「未分类」，不搬、不改名，旧版本照样能退回；原来的 `my_<名字>` 工具没有了，改成 `procedure_run("未分类/<名字>")`。想归到某一类，就带上 `category` 重新保存一次（平铺的旧文件留着，不要了自己删）。带 `extract` 的操作如果本来就可能读到空，升级后会报"没跑通"，在那一步加 `allowEmpty: true` 即可；旧版本文件不改写，只在最新版失败时读来试。
   - 她用电脑：默认关，升级后什么都不变；不加表，不写任何文件。打开后多一个 `desktop` 工具，关掉就撤走。
3. **宿主里已有会话的用户**：补读只回放会话消息，平台记录只在她的操作真正运行时写入，补读既不产生也不遗漏它们；范围外的会话不会因为操作或补读进入归档。

信箱对三批人：跟着「她用电脑」，那个开关默认关，没打开的什么都不发生；已经开着「她用电脑」的老用户升级后信箱就开始听，控制台那一行写着；老用户的归档、日记、已有操作都不受影响，信箱不写任何文件，只有在控制台改过不理会的名单才在 `world.json` 里多一项 `inboxIgnore`；升级后没改过名单的，三批人都从默认名单开始，Windows 自己的程序不再报；只有宿主会话的用户也一样，信箱里的东西不进归档，只有她自己去读的内容才会进。

## 风险

让程序操作网页，可能触发平台的风控，也可能违反平台的服务条款，账号可能被限制或封禁。建议只用专门的小号，不要用你重要的账号登录她的浏览器。插件不保证不被识别为自动化，也没有可靠的"安全频率"。对谁开口不设限：她能用这个浏览器做你的账号做得到的事，包括发私信和评论，需要约束就在人设和世界提示词里写明。

她用电脑时，能看到她打开的窗口里的一切，能用你在这台电脑上登录着的所有账号（微信、你浏览器里的网站）。自动操作可能触发平台风控，微信尤其敏感。她在后台操作，你在用电脑时也照样能动；随时关掉「她用电脑」就收回。

本机上任何程序都能读 `<世界目录>/browser/DevToolsActivePort`，据此驱动她已登录的浏览器，所以不要以同一个系统用户运行不可信的程序。

## 验证边界

已在 Windows 11 家庭中文版（10.0.26200）、Microsoft Edge 156.0.4314.58 上用真实浏览器测过启动、调试端口（不需要 `--remote-allow-origins`）和页面原语。

尚未验证：macOS 和 Linux；只有 Chrome 没有 Edge 的机器；真实的 B 站页面；真实 DSH 宿主里的工具注册。

她用电脑：在同一台机器上（2560×1600，175% 缩放）用 `win32.ps1` 测过，全程你的鼠标位置和前台窗口都没变：第一次调用要编译脚本里的 C#，约 2 秒；截微信 4.x 的窗口 1280×1029，约 0.1 秒。在微信搜索框上后台点击、输入 `test`、退格、`ctrl+a` 全选都生效；`ctrl+a` 起初不生效，因为 Qt 读的是左 Ctrl（`VK_LCONTROL`），两个都设上才行。后台按 Esc 把微信收进托盘，再 `open 微信`：先点「显示隐藏的图标」再点微信的图标，微信正常弹出。它弹出后会把自己拉到前台，并且按 Windows 的前台锁不让别的进程拿回来，所以还焦点之前先发一个不带按键的键盘事件（键码 0，没有程序响应它），让插件这边算作"最后有输入的进程"；之后焦点还给原来的窗口并保持住。真机测试设 `DSH_WORLD_DESKTOP_TEST=1`，只读。中文输入起初是乱码（投递用了 ANSI 版的 `PostMessage`），改成 `PostMessageW`。微信的「朋友圈」发表框打开时，主窗口不接收输入（像对话框一样把主窗口挡住）。从开始菜单启动记事本跑通了，焦点也还回来了；Win11 的记事本不接收投递的字符。尚未验证：改过之后在微信里输入中文；最小化窗口的原地还原；她看截图点坐标的准确度；DPI 不感知的老程序上坐标对不对。
