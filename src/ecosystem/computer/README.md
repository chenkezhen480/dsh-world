# 她自己的浏览器与自己存的工具

DSH 端代码在 `src/ecosystem/computer/`。插件只提供一个她自己的浏览器和一组通用的页面原语；不含任何平台（B 站等）的代码。某个网站怎么用，由她自己用原语摸索，走顺了就存成她自己的工具，以后直接回放；网站改版把工具弄坏了，由她自己重新走通再存。使用当前的家，不创建第二份 AI、人设或记忆。

## 开启

- 配置里写 `computer: true`，重载插件或重启 DSH。没写时控制台不显示这一项。
- 控制台概览的「接入」卡片里出现开关「她的浏览器」，默认关；卡片下有 Edge 状态（找不到 Edge / 未打开 / 运行中）、她的工具列表与各自最近一次结果，以及「打开她的浏览器」按钮。
- 第一次用时她的浏览器窗口出现在桌面上。要登录某个网站，请在那个窗口里自己扫码或输入，登录态留在 `<world>/browser/`。

## 浏览器

- 用系统自带的 Microsoft Edge（也会找 Chrome），以 `<world>/browser/` 为独立配置目录，开可见窗口，通过 DevTools 协议（CDP）控制。不是你日常用的那份 Edge，也看不到你的书签和登录。
- 所有操作都是浏览器内部派发的输入事件，**不使用你的鼠标和键盘**，窗口被别的东西挡住也照常工作。
- 编号在同一个标签页里不重复；页面里元素没了，旧编号会报错让她重读，不会点到别的元素上。点击时目标被别的元素盖住会拒绝。输入会替换输入框里原有的内容。
- 世界停止或关闭模块时，插件断开连接并清空等待中的操作，不关 Edge 进程（关掉会丢她开着的页面），由你自己关。Edge 被关掉后，下次她用时重新打开。

## 工具

只挂在家会话里，工作间和别的会话看不到。

| 工具 | 作用 |
| --- | --- |
| `page_open` | 在她的浏览器当前标签页打开地址，返回页面内容（同 `page_read`） |
| `page_read` | 读页面：每个可操作元素一行 `[编号] 角色 名称`，之后附可见文字；`page` 翻页，`ref` 只看某元素里面 |
| `page_click` | 点编号对应的元素 |
| `page_type` | 在编号对应的输入框里整段输入（中文也行）；`submit` 为真时再按回车 |
| `page_press` | 按一个键 |
| `page_scroll` | 向上或向下滚一屏左右，可指定元素 |
| `page_wait` | 等某段文字出现（最多 60 秒），或检查某个编号还在不在 |
| `page_shot` | 截当前页面一张图附在下一条消息里；只在读文字看不明白时用 |
| `page_eval` | 在当前页面里执行一段 JS，返回 JSON；十秒超时，结果截到 2000 字；只在她的浏览器页面里执行 |
| `procedure_save` | 把走通的步骤存成工具 `my_<名字>` |
| `procedure_list` | 列出她的工具和各自最近一次结果 |
| `my_<名字>` | 她存下来的工具，每个文件一个，不调模型，逐步回放 |

返回都很短：页面读取按页截断，脚本结果截断，截图不会自动附带。

## 工具文件

`<world>/procedures/<名字>.json`。工具说明里写明了这个路径，她可以用文件工具直接读和改。保存时插件先校验，不合格不落盘并说明哪里不对（文件里写了不认识的键也会被拒绝，免得一个拼写错误悄悄变成"任意链接"）；同名覆盖前，旧版本存成 `<名字>.v<n>.json`。已有的工具文件在启动时全部注册，格式不合格的跳过并登记故障，不影响其他工具。

顶层字段：

| 字段 | 说明 |
| --- | --- |
| `name` | 小写字母开头，只用小写字母、数字、下划线，2 到 41 个字符；工具名为 `my_<name>` |
| `description` | 她自己写的说明 |
| `params` | `{ 名字: { type: string｜number｜boolean, required?, description? } }` |
| `steps` | 1 到 40 步，每步只有一个动作 |
| `onAlarm` | 为真时每次闹钟前自动跑一次；不能有必填参数，也不能有向外发出的步骤 |
| `summary` | 闹钟前那一行的模板，可用 `{{count}}` 和脚本 `as` 存下的值 |
| `messages` | 把 `extract` 的行写进归档，见下文 |

步骤（文字里的 `{{参数}}` 会代入）：

| 动作 | 写法 |
| --- | --- |
| `open` | 地址 |
| `click` | 锚点 |
| `type` | `{ into: 锚点, text }` |
| `press` | 键名（与 `page_press` 相同） |
| `wait` | `{ text｜anchor｜url, seconds? }`，最多 60 秒 |
| `check` | `{ text｜anchor｜url }`，最多等 3 秒，还不满足就停 |
| `extract` | `{ list: 锚点, fields: { 名: 锚点, 可加 attr }, limit? }`，`limit` 默认 8、最多 20，字段最多 12 个；字段只写 `attr` 时读列表项自己的属性 |
| `script` | JS，可 `return`；`as` 把结果存成值 |

`extract` 和带 `as` 的 `script` 可加 `allowEmpty: true`，表示这一步本来就可能是空的（比如没有未读），见下文。

`click`、`type`、`press`、`script` 可加 `outward: true`，表示这一步会向外发出东西。锚点是 `{ role?, name?, text?, css?, nth? }`，`role`、`name` 取 `page_read` 里看到的，至少给一个；`nth` 从 0 数。工具里不存坐标，也不存快照编号。

```json
{
  "name": "bili_unread",
  "description": "看 B 站消息页的未读",
  "onAlarm": true,
  "summary": "私信 {{count}} 条",
  "steps": [
    { "open": "https://message.bilibili.com/" },
    { "wait": { "text": "我的消息" } },
    { "extract": { "list": { "role": "listitem" }, "fields": { "who": { "role": "link" }, "text": { "role": "paragraph" } }, "limit": 8 }, "allowEmpty": true }
  ]
}
```

回放遇到找不到的锚点或不满足的 `check` 就停，返回第几步、期望什么、当前页面的简短快照。带 `outward` 的步骤失败一律报"未完成"，不自动重试。

**空的也算没跑通。**`extract` 一条都没有、某个字段每一条都是空的、带 `as` 的 `script` 结果为空（`null`、空字符串、空列表或全空的对象），都按失败报出第几步，不再返回"完成。"或空结果。网站改版后选择器找不到东西，最常见的样子就是"什么都没有"，不报错的话她会以为"没有新私信"。本来就可能为空的那一步标 `allowEmpty: true`。

**新版不行就退回旧版。**最新版没跑通、而且还没有任何向外的动作时，按从新到旧再试最近 3 个旧版本（`<名字>.v<n>.json`，和较新版本完全相同的、已经不合格式的、参数对不上这次调用的跳过）。网站灰度或 A/B 测试时新旧页面会同时存在，为新页面修的版本到旧页面上可能跑不通。旧版本跑通了就用它的结果，后面附一句"最新版第几步没跑通，这次退回第几版"，`procedure_list` 里也记着；闹钟前那一行后面注"用的第几版"。全都不行时，报最新版的失败。

这两条的依据是模拟站点上的对比实验：空结果算失败后，不报错的失败从 105 次回放降到 0；退回旧版后，修复把旧页面修坏的从 9 次降到 0，学会、改版、修复全程走通的工具从 9/25 升到 16/25。

## 闹钟前回放

闹钟响起前，插件在一个单独的标签页里依次跑所有 `onAlarm` 的工具（整体约 60 秒，单个约 20 秒），跑完关掉这个标签页，不打扰她正在用的页面。每个工具留一行，接在闹钟文字（和微信群动态）后面，成功或失败都照实写：

```
my_bili_unread：私信 2（阿明）
my_bili_unread 没跑通（第 3 步找不到「回复我的」）
```

失败或超时不会拖住闹钟：闹钟不带这一行照样送出，同时登记一条故障。闹钟前的回放不在任何会话里，**不写归档**。

## 归档

工具可以用 `messages` 声明：`extract` 出来的哪些行是消息、各字段对应归档的哪一项。字段是 `channel`、`conversationType`（`private` 或 `group`）、`accountId`、`conversationId`、`messageId`、`speakerId`、`content` 必填，`speakerName`、`conversationName`、`occurredAt`、`outgoing` 可选；除 `channel` 和 `conversationType` 写死外，其余是 `{{字段}}` 模板，`outgoing` 算出 `true` 表示是她自己说的。

- 只有她自己在家会话里调用工具时读到的才进归档（`archive.sqlite`，`memory_find` 能找到）；按平台消息 ID 去重，再读一遍不会重复。
- 只在归档范围内写入；会话不在范围里时，工具结果注明"没有记"。
- 身份字段缺失或不合格的行跳过，工具结果里写"跳过 n 条"。
- 写归档失败不会让她的工具失败：读到的结果照给，后面补一句没记进去的原因。

## 文件位置

| 位置 | 是什么 |
| --- | --- |
| `<world>/browser/` | 她的浏览器配置，**含各网站的登录态**，不要外传、不要放进云盘或仓库 |
| `<world>/procedures/` | 她的工具 `<名字>.json` 和旧版本 `<名字>.v<n>.json`；这些是她的原件，插件只在她保存时写 |

备份世界目录时这两个都会带上，注意第一个的内容。

## 对三批人

1. **没用过插件的新用户**：默认关闭，什么都不变。打开后没有任何工具，从零开始由她摸索；归档里没有平台记录，直到她的工具第一次读到消息。
2. **已经用过插件的老用户**：不加表，不改任何已有文件。新增目录 `<world>/browser/` 和 `<world>/procedures/`。模板、她自己的 `alarm.md`、日记、自述不动；闹钟前的那一行接在模板渲染之后。工具文件是她的原件，插件只在她保存时写，并保留旧版本。
   - 在这个功能的开发版里存过工具的：带 `extract` 的工具如果本来就可能读到空，升级后会报"没跑通"，在那一步加 `allowEmpty: true` 即可；旧版本文件不改写，只在最新版失败时读来试。
3. **宿主里已有会话的用户**：补读只回放会话消息，平台记录只在她的工具真正运行时写入，补读既不产生也不遗漏它们；范围外的会话不会因为工具或补读进入归档。

## 风险

让程序操作网页，可能触发平台的风控，也可能违反平台的服务条款，账号可能被限制或封禁。建议只用专门的小号，不要用你重要的账号登录她的浏览器。插件不保证不被识别为自动化，也没有可靠的"安全频率"。对谁开口不设限：她能用这个浏览器做你的账号做得到的事，包括发私信和评论，需要约束就在人设和世界提示词里写明。

本机上任何程序都能读 `<世界目录>/browser/DevToolsActivePort`，据此驱动她已登录的浏览器，所以不要以同一个系统用户运行不可信的程序。

## 验证边界

已在 Windows 11 家庭中文版（10.0.26200）、Microsoft Edge 156.0.4314.58 上用真实浏览器测过启动、调试端口（不需要 `--remote-allow-origins`）和页面原语。

尚未验证：macOS 和 Linux；只有 Chrome 没有 Edge 的机器；真实的 B 站页面；真实 DSH 宿主里的工具注册和提示词缓存（保存工具会让下一次请求的缓存失效一次）。
